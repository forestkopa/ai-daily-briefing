# AI 日报看板 · 服务器部署手册

> 目标：把 AI 日报看板上线到 `https://daily.forestkopa.top`
> 服务器：公司 Win10 机器（已跑 kanban.forestkopa.top 的那台），**已装 Python 3.8.8**
> 方案：**方案乙** —— 服务器自己抓 RSS、自己渲染 HTML，全自动，零 token

---

## 0. 一句话说明

服务器上跑两个东西：

| 组件 | 作用 | 实现 |
|---|---|---|
| **取数器** | 每天定时抓 RSS → 生成 HTML | Python 脚本（`cli.py`），跑在独立 venv 里 |
| **静态服务** | 把 HTML 通过 HTTP 暴露出去 | `server.js`（Node，零依赖） |

cloudflared 隧道加一条 `daily.forestkopa.top → localhost:5190`，对外即可访问。

**与 kanban 完全隔离**：端口不同（kanban 5181 / daily 5190）、服务名不同、目录不同、隧道 ingress 各自一条。只有一样东西是共用的 —— **同一条 cloudflared 隧道**，改配置重启时 kanban 公网会闪断 3~5 秒。

## ⚠️ 2. 最重要的一个坑：feedparser 版本

**Python 3.8 不能装 feedparser 6.0.13 或更高。** 它们的 `requires_python` 是 `>=3.10`。

| feedparser 版本 | 要求 Python | 3.8.8 能用 |
|---|---|---|
| 6.0.14（开发机用的） | `>=3.10` | ❌ |
| 6.0.13 | `>=3.10` | ❌ |
| **6.0.12** | `>=3.6` | ✅ 推荐 |
| 6.0.11 | `>=3.6` | ✅ |

**部署脚本已自动处理**：检测到 Python ≤3.9 就装 `6.0.12`，检测到 ≥3.10 就装 `6.0.14`。

> 代码只用了 `feedparser.parse(url, agent=...)` 这一个接口，是 feedparser 最稳定的核心 API，6.0.11 / 6.0.12 / 6.0.14 行为一致，**无需改代码**。

**另一个已修的兼容点**：`fetch_rss.py` 原来有 `per_section: int | None`（3.10+ 语法），已改为 `Optional[int]`。

### 补充：Python 找不到时怎么办（实测踩过）

有些机器上 `python` 命令指向的是应用商店占位符，真正的解释器**只能通过 `py` 启动器访问**。
此时 `preflight.ps1` 会显示真实路径（如 `3.8.8 (C:\Windows\py.exe)`），说明能建 venv，**不用担心**。

部署脚本已会自动依次尝试 `python` → `py`，并通过 `py -0p`
把「已注册但不在 PATH」的解释器也列出来。如果还是找不到，手动指定即可：

```powershell
.\deploy-python.ps1 -PythonPath "C:\Windows\py.exe"
```

**怎么自查**（管理员 PowerShell，两行出结果）：
```powershell
python --version        # 报错或秒退 = 是占位符
py -0p                  # 列出所有真实解释器及其路径
```

## 4. 四步上线

### 第 0 步：先自检（1 分钟，只读不写）

**以管理员身份**打开 PowerShell，`cd` 到部署包目录：

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
.\preflight.ps1
```

它会逐项报告，标红的先解决，然后重跑一次：

| 检查项 | 说明 |
|---|---|
| 管理员权限 | 必须有 |
| 端口 5190 | 是否空闲 |
| Node.js | server.js 依赖 |
| Python | 版本 → 自动决定装哪个 feedparser |
| pypi.org | 装依赖要用 |
| nssm.exe | 服务注册要用 |
| cloudflared | 顺便判断隧道是命名隧道还是 Quick Tunnel |
| kanban 隔离 | 确认互不影响 |

> 它**只读**，随便跑，不会改任何东西。

### 第 1 步：一键部署

```powershell
.\deploy-python.ps1
```

脚本会自动做完 6 件事：

1. 环境自检（管理员 / Python 版本 / Node / NSSM / 端口）
2. 创建运行目录 `D:\ai-daily-briefing`，拷贝 5 个脚本
3. **创建独立 venv 并安装 feedparser**（自动选对版本）
4. 注册 NSSM 服务 `ai-briefing-server`（开机自启，崩溃自动拉起）
5. 立即跑一次取数（首屏有数据）+ 本地探活
6. 注册每日定时任务 `ai-briefing-update`（**每天 08:30** 自动更新）

常用参数：

| 参数 | 说明 | 默认 |
|---|---|---|
| `-InstallDir` | 安装目录 | `D:\ai-daily-briefing` |
| `-Port` | 服务端口 | `5190` |
| `-TaskTime` | 每日更新时间 | `08:30` |
| `-PythonPath` | 手动指定 python.exe | 自动找 PATH |
| `-NodePath` | 手动指定 node.exe | 自动找 PATH |
| `-SkipTask` | 不建定时任务 | - |

### 第 2 步：本机验证

```powershell
# 健康检查
curl http://127.0.0.1:5190/healthz

# 浏览器打开看效果
start http://127.0.0.1:5190/
```

看到当日 AI 日报页面即成功。

### 第 3 步：接入公网域名（用脚本，别手工改 YAML）

> 详细说明见 **`Cloudflare_操作清单.md`**。这里只给最短路径。

**自动插入 ingress**（脚本会自己备份、去重、插到兜底条目之前、校验，失败自动回滚）：

```powershell
.\add-ingress.ps1 -Hostname daily.forestkopa.top -Port 5190
```

它会问你「现在重启隧道吗」，按 `y` 即可。**重启瞬间 kanban 会闪断 3~5 秒**，避开业务高峰。

想先干跑看看会改什么（不写任何文件）：

```powershell
.\add-ingress.ps1 -Hostname daily.forestkopa.top -Port 5190 -WhatIf
```

**然后只剩一步（只能在 Cloudflare 后台做）**：给 `daily.forestkopa.top` 加一条 CNAME 指向隧道 —— 照抄 kanban 那条的 Target，只把 Name 改成 `daily`，代理橙云开着。

> **不想用脚本？手工改法**：编辑 `C:\Users\Administrator\.cloudflared\config.yml`，
> 在 `ingress` 的**兜底条目之前**插入 `- hostname: daily.forestkopa.top` / `service: http://localhost:5190` 两行。
> **三个铁律**：① 用空格不要用 Tab ② `service:` 与 `hostname:` 左对齐 ③ 兜底条目（无 hostname 那条）必须留在最后。
> 改完重启：`Get-Service | Where-Object { $_.Name -like '*cloudflared*' }` 查出服务名后 `Restart-Service <服务名>`。

验证：浏览器打开 `https://daily.forestkopa.top`。

## 5. 日常运维

### 手动更新一次

```powershell
D:\ai-daily-briefing\venv\Scripts\python.exe D:\ai-daily-briefing\cli.py --out D:\ai-daily-briefing\data
```

常用参数：

| 参数 | 说明 | 默认 |
|---|---|---|
| `--hours N` | 抓取时间窗（小时） | 48 |
| `--out DIR` | 输出目录 | exe/脚本同级 `data\` |
| `--keep-days N` | 归档保留天数，0=不清理 | 30 |

`server.js` 侧的启动参数（一般由部署脚本填好，不用手改）：

| 参数 | 说明 |
|---|---|
| `--port N` | 监听端口，默认 5190 |
| `--root DIR` | 静态根目录，默认 `server.js` 同级 `data\` |
| `--py PATH` | 抓取器可执行文件：venv 里的 `python.exe`，或 exe 版就是 exe 本身 |
| `--cli PATH` | 取数脚本路径。**传空字符串 `""` 表示 `--py` 本身即程序**（exe 模式） |
| `--cooldown N` | 刷新冷却秒数，默认 60 |

### 页面上的「刷新」按钮

看板右下角（回到顶部按钮上方）有一个圆形刷新按钮。点它 = **让服务器重新抓一遍 RSS**，
不是浏览器刷新。抓完页面会自动重载，右上角弹出「已更新」提示。

它依赖服务端的两个接口：

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/refresh` | POST | 触发一次真实抓取；返回 `202` 表示已受理 |
| `/api/status` | GET | 查当前状态，前端每 2.5 秒轮询一次，`state=ok` 后自动重载 |

**自带保护，不用担心被点爆：**

- **单飞锁**：同一时刻只允许一个抓取在跑，重复点返回 `429 {"reason":"busy"}`。
- **冷却**：距上次成功不足 60 秒，返回 `429 {"reason":"cooldown","retryAfter":N}`。
  冷却秒数由服务注册命令里的 `--cooldown 60` 控制，想改就改这里。
- **超时**：单次抓取超过 5 分钟自动杀掉子进程，不会把服务拖死。

> 按钮是**开放**的——知道网址的人都能点。这是刻意的（页面本身也没有鉴权）。
> 如果哪天想收紧，在 `server.js` 的 `/api/refresh` 分支里加一个 token 校验即可。

**命令行等价操作**（想排除前端因素时用）：

```powershell
# 触发一次
curl.exe -X POST http://127.0.0.1:5190/api/refresh
# 看状态
curl.exe http://127.0.0.1:5190/api/status
```

> 注意端口换成你实际部署的端口（默认 5190）。
> 页面用 `file://` 直接打开时按钮会自动隐藏——它需要服务端配合。

### 常用服务命令

```powershell
nssm status  ai-briefing-server     # 查看状态
nssm restart ai-briefing-server     # 重启
```

## 6. 后续更新（重要）

改动代码后怎么更新到服务器？**不用重新拷贝整个部署包**，用增量更新包。

### 6.1 本地：生成更新包（一条命令）

在开发机（`D:\WorkBuddyData\ai-daily-briefing\`）：

```powershell
python make_update.py
```

产物：`dist_package\ai-briefing-update.zip` —— **只有 ~27 KB**（对比全量包 8 MB）。

| 打包了什么 | 说明 |
|---|---|
| `update.ps1` | 更新脚本（服务器端运行） |
| `更新.cmd` | **双击入口**（绕过 PowerShell 执行策略） |
| `更新说明.md` | 给现场看的一页说明 |
| 5 个源文件 | `fetch_rss.py` / `build.py` / `clean_cache.py` / `cli.py` / `server.js` |

**绝不打包**：`data/`（数据）、`venv/`（环境）、`logs/`（日志）、任何配置。
→ 所以包极小，而且**不可能误覆盖服务器数据**。

只改了某一个文件时（更快）：

```powershell
python make_update.py --only build.py
```

### 6.2 服务器：应用更新（双击）

1. 把 `ai-briefing-update.zip` 拷到服务器
2. **解压到任意目录**（⚠️ 不要解压进 `D:\ai-daily-briefing` 里面）
3. **双击 `更新.cmd`** —— 完成

脚本会自动：

1. **定位服务的真实目录**（可能与 `-InstallDir` 不一致，见 §6.3 说明）
2. 备份现有 5 个源文件到各目录的 `backup\<时间戳>\`
3. 逐个替换（**两处目录都替换**，确保服务真正用到新文件）
4. 若 `server.js` 变过 → 查找 `nssm.exe` 并自动重启服务 + 探活
5. **重新生成页面 HTML** → UI / 模板改动立刻可见，不用等次日 08:30

> **为什么用 `.cmd` 双击？** 服务器 Windows 默认 PowerShell 执行策略是 **Restricted**，
> 直接跑 `.ps1` 会被拒绝。`.cmd` 不受该策略限制，且内部已带 `-ExecutionPolicy Bypass`。
>
> 想用 PowerShell 也可以：
> ```powershell
> powershell -ExecutionPolicy Bypass -File .\update.ps1
> ```
>
> 只想替换文件、不做重启和重新生成：
> ```powershell
> powershell -ExecutionPolicy Bypass -File .\update.ps1 -NoRestart -NoRegen
> ```
>
> **`nssm` 不在 PATH 里**，所以别手敲裸 `nssm restart ai-briefing-server`（必然报
> "无法将 nssm 项识别为..."）。要用完整路径，例如：
> ```powershell
> & "C:\Users\Administrator\Desktop\ai-briefing-deploy\nssm.exe" restart ai-briefing-server
> ```
> 或者直接用 Windows 自带的服务管理：
> ```powershell
> Restart-Service ai-briefing-server
> ```

### 6.3 更新后要不要重启服务？

**都不用你管，更新脚本已经把该做的都做完了。**

| 改了什么 | 脚本自动做什么 |
|---|---|
| 取数/模板脚本（`fetch_rss.py` / `build.py` / `clean_cache.py` / `cli.py`） | **自动重新生成一次页面**，立刻可见 |
| `server.js` | **自动重启**服务 + 探活 |
| 服务没注册（首次部署前） | 跳过重启，只替换文件 |

> ⚠️ **以前这里的说法是"不用重启，等次日 08:30 定时任务生效"——那是个坑。**
> 改了 UI / 模板后，页面 HTML 还是上次生成的旧产物，用户打开看到的还是旧样式，
> 会误判成"更新失败"。现在脚本会自己重跑一次生成。

脚本还会**自动定位服务的真实目录**（服务的 `AppDirectory` 可能与 `-InstallDir` 不一致，
例如 exe 版部署时服务目录就是解压目录），并**同时替换两处**，避免"替换成功但服务没用到"的假成功。

想手动立即刷新一次（脚本已做，一般不需要）：

```powershell
D:\ai-daily-briefing\venv\Scripts\python.exe D:\ai-daily-briefing\cli.py --out D:\ai-daily-briefing\data
```

### 6.4 更新出问题了怎么回滚

每次更新都会自动备份。回滚：

```powershell
# 看有哪些备份
dir D:\ai-daily-briefing\backup

# 用最新那份还原（把 <时间戳> 换成实际目录名）
Copy-Item "D:\ai-daily-briefing\backup\<时间戳>\*" "D:\ai-daily-briefing\" -Force
```

然后 `nssm restart ai-briefing-server`。

### 6.5 什么时候需要重新部署（而非增量更新）

只有这些情况才需要重跑 `deploy-python.ps1` 或手工处理：

| 情况 | 处理 |
|---|---|
| **新增依赖包**（如又用了新库） | 手工：`D:\ai-daily-briefing\venv\Scripts\pip install <包>`（**注意 3.8 版本限制**） |
| 改了端口 / 服务名 / 定时时间 | 重跑部署脚本，或直接 `nssm set` / `schtasks /Change` |
| 换了服务器 / 首次部署 | 用全量部署包 |

## 8. 与 kanban 的隔离清单

| 维度 | kanban | AI 日报 | 是否冲突 |
|---|---|---|---|
| 端口 | 5181（正式）/ 5180（demo） | **5190** | 否 |
| NSSM 服务名 | `kanban-*` | `ai-briefing-server` | 否 |
| 定时任务名 | `kanban-*` | `ai-briefing-update` | 否 |
| 运行目录 | kanban 目录 | `D:\ai-daily-briefing` | 否 |
| Python 环境 | （各自独立） | **独立 venv** | 否 |
| 域名 | kanban.forestkopa.top | daily.forestkopa.top | 否 |
| **cloudflared 隧道** | 共用 `2bbff070-...` | **同一隧道** | ⚠️ 见下 |

**唯一的耦合点**：两条域名共用一条隧道。改 `config.yml` 后重启 cloudflared，会让 kanban 公网闪断 3~5 秒。除此之外互不影响 —— 各自服务独立启停、独立升级、独立崩溃。

## 9. 常见问题

**Q：`deploy-python.ps1` 跑到 `[2/6] 创建虚拟环境...` 就没下文了，不报错也不回提示符？**
A：**这是最容易踩的坑。** 几乎可以确定是 Windows 自带的
**Microsoft Store「应用别名」占位符**在作怪：

```
C:\Users\<你>\AppData\Local\Microsoft\WindowsApps\python.exe   ← 只有 0 字节，是假的
```

`Get-Command python` 会找到它（所以"能查到 Python"是假象），但它是 0 字节的壳，
拿它建 venv 必然失败，脚本随即退出 —— 错误信息还常常一闪而过看不见。

**一行确诊**（管理员 PowerShell）：
```powershell
(Get-Item "$env:LOCALAPPDATA\Microsoft\WindowsApps\python.exe").Length
# 输出 0 就是它。真解释器通常在这里：
Test-Path "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe"
```

**解决**（二选一）：
```powershell
# 方案 1：显式指定真解释器（推荐）
.\deploy-python.ps1 -PythonPath "$env:LOCALAPPDATA\Programs\Python\Python312\python.exe"

# 方案 2：完全绕开 Python，走 exe 模式（不需要装 Python）
.\deploy-nssm.ps1
```

> 新版 `deploy-python.ps1` 已能**自动跳过**这个占位符（会打印一行 `[!] 跳过应用商店占位符`）。
> 若你还是遇到"没下文"，请先用上面的两行命令确认字节数，再带 `-PythonPath` 重跑。

**Q：怎么事先知道服务器上会不会有这些坑？**
A：先跑只读自检，它会把 Python（含真伪判定）、端口、Node、nssm、pypi、cloudflared、kanban 隔离一次查完：
```powershell
.\preflight.ps1
```
看到 `[v] Python 3.12.10 (...Python312\python.exe)` 这种带**真实路径**的行才算过关。
如果显示的是 `WindowsApps` 路径，就是踩了上面的占位符。

**Q：`daily.forestkopa.top` 打不开，502 / 1033？**
A：按顺序排查 ——
1. `curl http://127.0.0.1:5190/healthz` 本机通不通？不通 → `nssm status ai-briefing-server`
2. 本机通但公网不通 → ingress 写错或没重启 cloudflared
3. 看 cloudflared 日志

**Q：装 feedparser 报错 / 超时？**
A：服务器访问 pypi 受限。改用国内镜像：
```powershell
D:\ai-daily-briefing\venv\Scripts\python.exe -m pip install feedparser==6.0.12 -i https://pypi.tuna.tsinghua.edu.cn/simple
```

**Q：`pip` 报 `No matching distribution found`？**
A：多半是版本选错。Python 3.8 必须用 `feedparser==6.0.12`（不是 6.0.14）。

**Q：页面是空的 / 显示昨天的？**
A：手动跑一次更新命令看输出。若 RSS 抓取失败，多半是服务器出网受限 —— 该方案要求服务器能直连外网（RSS 源含量子位、IT之家、InfoQ 等国内站，一般没问题）。

**Q：定时任务没执行？**
A：任务以 **SYSTEM** 身份注册（无需登录即可跑）。检查：
```powershell
schtasks /Query /TN ai-briefing-update /V /FO LIST
```
看「上次运行结果」，非 0 即失败。

**Q：磁盘会一直涨吗？**
A：不会。每天归档一个 HTML（约 40 KB），第 5 步自动删 30 天前的归档。一年也就 ~15 MB。

**Q：能不能不用 Node / 不用 NSSM？**
A：可以。`cli.py` 直接 `--out` 到任意目录，配合任何静态服务器都行。Node + NSSM 只是本方案选的最省事组合。

## 附录 A：exe 备用方案

若服务器 Python 被策略限制、或想彻底摆脱 Python 依赖：

```powershell
Set-ExecutionPolicy -Scope Process Bypass -Force
.\deploy-nssm.ps1
```

它用 `ai-briefing-update.exe`（8.0 MB 单文件，免 Python），流程与 Python 版一致。

**它注册服务时用的是这条命令** —— 注意 `--py` 指向 exe 本身，`--cli` 传空：

```
nssm install ai-briefing-server <node.exe> "server.js --port 5190 --root <data> --py <exe路径> --cli \"\" --cooldown 60"
```

`--cli ""` 是约定：**空字符串 = “`--py` 本身就是可执行程序”**，于是 `server.js` 用
`<exe> --out <data> --hours 48 --keep-days 30` 调用它做页面刷新，不会去拼不存在的 `cli.py`。

> exe 已在本机真机验证：不借任何 Python 环境，5 步全绿（11 信源 / 34 条 / 0 乱码 / 0 英文）。
> 两种模式的页面刷新也都实测通过：venv 模式 → `ok 已更新` + `429 cooldown`；
> exe 模式 → `ok 已更新` + `429 busy`，且 `latest.html` 内确实带刷新按钮。
